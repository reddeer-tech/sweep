What's New

Full Disk Access detection, fixed

If you'd granted Sweep Full Disk Access and it still showed the "Enable Full Disk Access" prompt, this release is for you.

macOS makes a protected file look absent rather than unreadable, and Sweep's check treated the first file it could see as the final word. That meant it stopped at a file it couldn't read and never tried the ones it could — so granting access changed nothing it reported.

The check now tries every probe and takes any successful read as proof, starting with the system permissions database that exists on every Mac. It also errs the safe way: if it genuinely can't tell, it says "not granted" rather than assuming the best, which previously left anyone who'd never opened Safari with no way to grant access at all.

Sweep now logs which file proved it, so if this ever misbehaves again the reason is visible rather than guessable.

Two things worth knowing about how macOS handles this, because they surprise almost everyone:

  • Every copy of an app needs its own grant. A copy in /Applications and a copy anywhere else are separate entries, even when they're byte-identical and signed the same way.
  • A permission entry can outlive the app that created it. If Sweep was granted access under an older version and the prompt keeps coming back, remove its row from the Full Disk Access list with the "−" button, add it again with "+", and quit and reopen Sweep.

Less pointless work in the background

The permissions screen kept re-checking for access every 1.5 seconds for as long as Sweep was open, even after you'd dismissed it and moved on. It now stops once it's out of the way.
