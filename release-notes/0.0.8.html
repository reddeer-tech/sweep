What's New

Nothing risky arrives pre-ticked

Sweep decides what's safe before it shows you anything, and this release changes what happens when it can't decide. Previously an unrated item defaulted to "safe, already selected". Now it defaults to "needs your judgement, unchecked".

That flipped four things that used to arrive pre-selected and shouldn't have: your Android Studio settings and plugins, backup copies of config files in your home folder (.zshrc.backup and friends), docker system prune -a, and superseded editor extensions. All four are still offered. None of them are ticked for you any more, and the ones that are real files now go to the Trash instead of being erased.

It no longer mistakes installed apps for removed ones

App Leftovers finds data left behind by apps you've deleted. It used to ask Spotlight whether an app was still installed, and treat "no answer" as "not installed".

That was wrong often enough to matter. On the test Mac, 4 of 149 installed apps were permanently missing from the Spotlight index, and which ones drifted between scans — so three consecutive scans each proposed a different set of still-installed apps for removal. One of them was Docker's container folder, which holds every volume you have.

Sweep now reads the installed-app list off the disk itself, and checks that it can see a known app before it trusts any answer. If it can't, the section stands down instead of guessing.

Your Time Machine snapshots, at last

The section that's supposed to show local snapshots — usually the real reason "System Data" is enormous — had a measurement bug that made it report zero every time. It has never once appeared. It does now: on the test Mac it found 19.8 GB across four snapshots, keeping the newest.

Related, and more important: Sweep used to thin every local snapshot after any clean, whether or not you'd asked. Clear a 200 MB browser cache and your entire local version history went with it, silently. That now only happens if you actually select the snapshots.

Big things Sweep couldn't see before

  • Xcode test device clones — 177 GB on the test Mac, the largest single item on the disk. 38 of the 44 clones couldn't even boot, their iOS runtime being long gone.
  • Simulator runtimes — removed with Apple's own command, and kept whenever a simulator still sits on them.
  • Agent build caches from XcodeBuildMCP, resolved back to the project each one belongs to.
  • Gradle and Homebrew, both keeping what you've actually used recently rather than just the highest version number.
  • Unity, and the Claude Cowork VM image.

Docker, in pieces

One "reclaimable Docker data" row became three you can choose between: unused images, stopped containers, and build cache. Volumes and Docker.raw are still never touched. Sweep also tells you that pruning returns space to Docker's own pool rather than to macOS, so you're not left wondering why your free space didn't move.

Keeping what you use, not what's newest

"Newest" is a guess. "Active" is a fact. Where a tool records which version it's using, Sweep now reads that instead of sorting version numbers: your live pnpm store, the Gradle versions you built with this month, the Android system images your emulators actually boot from, the runtimes your simulators sit on.

Sorting by version number would have deleted the live pnpm store and a Gradle version used the day before.

Straight answers

If you cancel the administrator password prompt, Sweep no longer claims it freed the space anyway. If a section can't run because the app that owns those files is open, it says so instead of vanishing from the list.
